## 1\. Apply `spark-match.patch`

Attached. Seven files, +211/−34. It applies clean to `e463b0b` and builds with zero type errors on your pin — I verified both on a fresh clone.

```bash
git apply spark-match.patch
npm run build
```

What it does, and why each part matters:

**a. The 28 pair icebreakers you wrote this morning become reachable.** `index.ts:53` passes `null` for `theirs`, so `pickIcebreaker` skips the pair branch every time and half your content bank can never appear. The patch adds `pastPartnerSparks()` in `pairing.ts`: it reads the synced wall for this table, finds the most recent past human who shares the most with you (using your `overlapScore`, which was written and never called), and hands their sparks to `pickIcebreaker`. No new round-trip, no new component — sparks now ride with each `WallEntry`, so every client already has them on arrival. When nobody else has ever answered at that table it returns `null` and behaviour is exactly as before.

**b. The match can no longer dead-end.** `server.ts:181–187` matches on same prompt + same answer, or returns nothing — and nothing renders as *"Yours is the first answer like that."* That sentence is the empty venue, and a judge with unlucky picks will read it on their first tap. The patch replaces it with `findMatch()`, a four-rung ladder:

1. same prompt, same answer, shares a spark
2. same prompt, shares a spark
3. same prompt, same answer
4. anyone else on this wall

Rung 4 only fails if the player is literally the first human ever at that board. The rung number comes back in the ack so the client can phrase the reveal honestly — rung 1 says *"you both said"*, rung 4 says *"was here before you"*. Never claim a stronger match than the data supports; judges notice.

**c. The Spark Match is a screen, not a toast.** `index.ts:99` fires your signature moment as a seven-second `showToast` — the same disappearing box as "your answer is on the wall." The patch adds `showReveal()` and a `SparkMatch` component in `ui.tsx`: the other person's name at 72pt, the match line, the shared sparks as coloured chips in their emblem colours, the agree count, and a "Nice to meet you" button. It stays up until tapped. **This is the screenshot, the video's opening shot, and the thing a judge retells.** Nothing else in the project has that leverage per hour.

**d. One defensive line.** Entries persisted before this change have no `sparks` field, so the ladder reads `e.sparks ?? []`. Your founding entries get `sparks: []` explicitly. Nothing off disk is trusted for shape.

**Things the patch deliberately does not do:** it doesn't touch `chooseTable` (live seating is G4, and it's on the cut ladder — the cross-time pairing above already delivers the content win), and it doesn't add lanterns or the live simultaneous reveal (those are G2.5 in the plan; do them after this is deployed and seen on a phone).

## Things in the current code that will bite on a phone — not urgent today, due by G6 (31 Aug)

All verified against Decentraland's mobile parity tracker (updated 21 Aug 2026: *"Touch-only input — no mouse hover states"* and *"No Gestures for now"*).

* `plaza.ts:166, 213` — `hoverText` is the only tap affordance. Hover doesn't exist on touch. Needs a visible cue.
* `ui.tsx:50` — the UI canvas is `1920×1080` landscape with fixed-pixel panels. Phones are portrait. Needs measuring on the device, not reasoning about.
* `index.ts:43` — the only navigation after picking sparks is a six-second toast. A judge who looks away loses the thread, and nobody is there to re-explain.
* `plaza.ts:187` — the stand says "Today's Question" but the question itself is invisible until tapped. The retention mechanic should be readable from across the plaza.
* Rename anything called a "gesture" to a tap before someone builds a swipe.
